# MOSS / Supertonic 路由试验

本提交默认启用 MOSS / Supertonic 路由；1.5已在平台三容器完成699次请求，汇总失败0，但仍有1项RTF不达标及泰语部分输出异常。下述新前端另经单容器实机验证，尚未重交平台。
中文与泰语使用 MOSS TensorRT 后端（中文保留 1.3），英文、日文、德文、法文、俄文、西班牙文使用 Supertonic 3 TensorRT。
Supertonic 保留已试听的 F1、8 步、speed=1.05；随机数状态独立于其他实例。

`plugins.tts` 已配置：

```yaml
routing: moss_supertonic
supertonic_model_dir: /models/supertonic-3-trt-jp61
```

插件入口仍为 `TTS_PLUGIN=moss_tts`，现有 `model_dir` 仍指向 MOSS 模型包。
不设置 `routing` 时仍使用原 MOSS 路线。每个 MCP 实例独立拥有两个后端，不共享模型状态；两者均成功预热后才声明运行。

请求显式 `language` 优先，其次是配置语种，最后按现有字符及词汇规则识别。
短词、品牌名称和混合语种可能存在歧义，应显式指定语言。没有显式或配置语种的纯数字串（允许全角数字及空白分组）默认中文；该规则不改变显式外语。无数量上下文的长数字作为标识符逐位读，中文10位以上按3位起、后续4位分组，保留前导零。
这不是句内多模型切换：一条请求只选一个后端。泰语走 MOSS；其他未启用语言明确报错，不回退成英语。

## 模型与接口

Supertonic 目录必须包含 `duration_predictor.plan`、`text_encoder.plan`、`vector_estimator.plan`、`vocoder.plan`、`tts.json`、`unicode_indexer.json`、`F1.json`。
当前引擎只在 JP6.1 / TensorRT 10.4.0 上验证，来源为 Supertonic 3 revision `aafc6e32` 的本项目 TRT 构建结果；文本编码器和向量估计器使用混合 FP16（归约等敏感算子保留 FP32），时长预测器和声码器保持 FP32。不能直接用于其他 TRT 版本或 GPU。
代码来源、许可证及原 helper 校验值见 `perception/plugins/supertonic_runtime/NOTICE.md`。

Supertonic现在在原生Unicode处理和分块之前复用既有数学、量纲与已批准术语规则，避免平方符号被NFKD变成普通数字。不批量启用trial词条。模型权重、F1音色、8步和speed1.05保持；无需重建现有引擎，仍对展开后的实际token和预测时长执行原有界限。

2026-11-03验证：本机54条音频含六语种数学、独立公式、术语候选和普通句对照；Jetson单容器36请求及6次数字分组补测，无OOM，其他容器ID/PID不变。首轮36请求首PCM最大0.353秒、RTF最大0.733；这是适配器计时，不含MCP/ROS及三实例并发。六条普通句交付PCM逐样本一致，中文跨语种切换对照一致。分组手机号的ASR数字完整，逐数字停顿候选出现重复，未采用。音频、ASR和源码快照在项目outputs/v15-frontend*与outputs/v15-phone-orin-20261103；数学ASR使用同一预先展开口语参考，不能把符号/数字转写形式差异当作发音错误，也不等于榜单得分。
模型不得提交到 Git。`perception/supertonic_assets.json` 记录不可变 JuiceFS 路径、大小和 SHA256；Dockerfile 使用现有下载器校验安装。2026-11-02 包含 8 个资产、共 270,337,902 字节，旧 FP32 包为 415,938,366 字节。

Supertonic 首块字符预算为日语 40、其他语言 120，后续块为日语 80、其他语言 160；优先在标点和词间空白切分，再使用实际文本处理器校验含语言标签的 token 数不超过 384。块间停顿保持 0.3 秒。
这不是句内增量声码器流式：首 PCM 要等待第一文本块生成完毕。
旧 FP32 TRT profile 支持至多 512 个文本 token、512 个 latent 帧；当前混合精度文本/向量引擎上限收紧到 384 token / 192 latent 帧，适配器使用相同上限。时长预测超限时在分配音频缓冲前重新切分文本，不丢弃后半段。更小分块可能改变停顿和韵律，仍需听感验收。

现有 ROS 音频通道固定为 16 kHz 单声道 PCM16；Supertonic 原生 44.1 kHz 通过多相滤波重采样接入，不能直接改采样率标签。
实机试验同时保存原生和交付版 WAV，便于对照。ASR、听感以及完整 MCP/ROS 时延不能由适配器测试替代。

## Supertonic 临时显存

首轮完整框架测试在两个容器加载后宿主仅余约 1204 MiB，保护逻辑拒绝启动第三个，未发生 OOM。不能将单实例 RSS 外推为三个容器的系统内存需求。
根据 [TensorRT 内存 API](https://docs.nvidia.com/deeplearning/tensorrt/10.x.x/_static/python-api/infer/Core/ExecutionContext.html)，Supertonic 四个串行阶段改用 `create_execution_context_without_device_memory()`，设定所有输入形状后调用 `update_device_memory_size_for_shapes()`，复用该实例内的临时 GPU 缓冲。每个调用已同步，整个请求有实例锁。不同容器/实例不共享此空间，也不共享模型权重或状态。
MOSS 调用不传 workspace，保持原分配与 CUDA Graph 路径。权重、引擎、采样和音色没有变化。修改后 26 条单实例请求的 50 个 WAV 文件与修改前逐字节相同，产物 `outputs/routed-tts-lowmem-20261030/`。

## 内存回收补充（2026-11-02）

进一步实测后采用三项修改：纯 TensorRT 路径延迟导入 ONNX Runtime；引擎通过只读 mmap 反序列化，避免 Python 整文件副本；通用 IO 缓冲的扩容余量限制在旧容量的 25% / 64 KiB 两者较小值，不再每次翻倍。
MOSS 在请求结束后还释放 codec 的 CUDA Graph、输入输出及状态缓冲；保留 codec 引擎权重和执行上下文，下次请求重建图和绑定。帧图保留。销毁 codec 执行上下文的版本更省少量 RSS，但首 PCM 约 0.34–0.39 秒；保留上下文后中泰语首 PCM 约 0.25–0.29 秒，因此采用后者。进程内复用 TensorRT Runtime 的试验没有明显收益，已撤回。

同一测试机、同一混合精度模型包、相同 60 条顺序请求（20 条 × 3 轮）的对照：

| 请求结束后的指标 | 本轮修改前 | 本轮最终版 |
| --- | ---: | ---: |
| 进程 RSS | 1026.94 MiB | 1013.79 MiB |
| 进程 PSS | 1009.06 MiB | 995.91 MiB |
| PyTorch CUDA allocated | 49.06 MiB | 0.01 MiB |
| PyTorch CUDA reserved | 58 MiB | 4 MiB |

这些指标相互重叠，不能相加，也不是完整显存或宿主峰值。cgroup 读数还受文件缓存归属影响，不把其约 100 MiB 的下降全当成模型常驻收益。宿主可用内存在不同轮次有波动，未观察到与分配器下降等量的系统可用内存提升。

60 条 PCM SHA256 均与修改前相同，三轮输出一致；取消中文流后再次生成的 PCM 也与完整请求相同。最终首 PCM 最大 0.286 秒、RTF 最大 0.568，均为预热后适配器计时，不含完整 MCP/ROS。新增 5 项内存生命周期/加载测试通过，原前端、路由、分块和音频交付回归保持通过。
基线 `outputs/routed-memory-baseline-20261102/`，最终版 `outputs/routed-memory-final-20261102/`，对照 `comparison.json`。模型权重与音色未变。本轮减少了空闲分配器保留量，但常驻模型/运行库仍是主要占用，不能据此宣称三实例资源问题已解决。

最终三容器复测（`outputs/routed-memory-final-three-container-20261102-115010/`）加载并预热两个实例后，宿主最低可用 1777 MiB；预测无法保留 1024 MiB并加载第三个，保护退出，未启动第三个。没有执行并发推理压测；两个自有容器已清理，OOMKilled=false，其他四个容器 ID/PID 未变。相比上一轮的 1710 MiB有所改善，但测试间后台波动存在，不把差值全部归因于本轮优化。

## 文本读法与音频拼接（2026-11-03）

本次候选在原MOSS中文/泰语、Supertonic六外语路由上改善数学读法、分块接续、数字实体和块间静音。Supertonic F1、8步、speed=1.05及两套模型/TRT资产保持；中文普通句沿用原MOSS处理。无需重建模型引擎，平台仍按提交commit构建镜像。

- 数学与单位：Supertonic在原生Unicode归一化前复用既有数学/单位解析和已批准词条，避免上标平方被降为普通数字。不批量启用候选词库。普通小数调用各语种规则；版本、IP、日期、URL、代码和歧义千分位保持保守处理。
- 分块：保留首块120/后续160字符（日语40/80）、实际384token与latent192边界，优先完整句，再分句/词。非末块必须句中切分时使用续接逗号，日语末尾「、」不再被原生前端追加句号。时长重分块沿用相同末块标记，关闭/取消仍释放临时资源。
- 音频拼接：仅裁掉块边缘连续至少80ms的精确零PCM，保留20ms护边；额外块间静音300→80ms，块内停顿和所有非零采样保留。41条已有Orin录音238个接缝的静音中位数从0.882–1.158秒降到约120ms；这项统计来自离线重拼验证。
- 数字与邮箱：七语种的明确验证码/订单/序列号/电话语境按位分组，保留前导零和编号连字符。邮箱保留较长小写词、拼读短字母串，并显式读每个数字和符号。独立纯数字auto默认中文，显式语种仍优先；中文10位以上数字按3位起、后续4位分组并补句末标点。正文不强制新增句界。
